# 场景化检索与嵌入优化

参考 materials 中《从基础检索到生产级 AI 系统的 10 个 RAG 项目》，本次选择混合检索、上下文分块、候选排序和证据检查，应用于现有 Markdown 与 GitHub Stars 数据源。

| 场景 | 检索策略 | 嵌入策略 |
| --- | --- | --- |
| 仓库名、错误码、技术标识符或单词查询 | 关键词权重 0.8，精确仓库名加分 | 保留原始标识符 |
| 多词自然语言、中文问题 | 关键词权重 0.45，语义权重 0.55 | 本地文档加入文档名与章节名 |
| GitHub 仓库发现 | 每个仓库保留最高排名证据，避免同仓库占满结果 | README 按标题分段，附带稳定的描述、语言与主题 |
| 指定 owner/repo 的详细问题 | 保留同仓库多个证据片段 | README 保留章节名称；星数与更新时间只出现在元数据块 |
| 增量更新 | 保持既有用户与模型空间隔离 | 本地按内容缓存，Stars 复用同用户、同仓库、同嵌入空间的未变化文本向量 |

两路各取最多 max(30, top_k × 6) 个候选，以加权 reciprocal rank fusion 合并，降低不同分数尺度的影响，再使用有界关键词覆盖率与精确名称加分排序。未命中关键词且原始余弦相似度低于 0.3 的结果不进入融合；排名不能单独作为证据。

本地缓存按用户、模型 identity 与上下文文本隔离，最多保留 4096 个条目；进程重启后重新生成。Stars 在替换旧索引前完成嵌入，取消或失败保留旧分块。新 README 分块在下一次实际重新索引时生效，已有向量不会自动迁移；跳过已有仓库的导入流程不会触发重建。

限制：0.3 是初始启发式阈值，不是经过校准的置信度；不同模型需用真实查询评估。单词与中文无空格查询暂按关键词优先处理。当前排序是轻量规则，不是 cross-encoder。无嵌入配置的本地检索继续使用离线 BM25/TF-IDF。

建议准备固定标注集，覆盖错误码、精确名称、中英跨语言、相近项目区分、无答案、增量修改；分别测 Recall@k、MRR、无答案误召回率、检索延迟与嵌入调用数，再调整权重和阈值。本次自动化测试验证行为与缓存复用，未调用外部模型，也未声称真实召回率已提升。
